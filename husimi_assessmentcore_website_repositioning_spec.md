# Husimi / AssessmentCore Website Repositioning — AI Implementation Brief

## Objective

Reposition the current AssessmentCore website from a narrow **PDF-to-QTI SaaS product** into a broader, credible **assessment content + education technology services business**, while keeping AssessmentCore as the proprietary technology/product that powers delivery.

The public-facing company/brand is now:

- **Company brand:** Husimi
- **Domain:** `husimisolutions.com`
- **Assessment product/service brand:** AssessmentCore
- Preferred relationship wording: **AssessmentCore by Husimi**

The website must communicate that Husimi can take responsibility for real assessment-content work today, while AssessmentCore is the technology layer being developed to automate more of that work over time.

Do **not** present Husimi as a large team or mature enterprise. The business is currently founder-led.

Do **not** make unverifiable claims such as:
- “100% flawless imports”
- “absolute precision”
- “guaranteed accuracy”
- “our team of experts” unless real team members are explicitly provided later
- fake customer counts
- fake client logos
- fake testimonials
- fake case studies
- fake SLA/performance numbers

The site should look like a serious B2B assessment/content technology company, not a generic freelance agency and not an OCR demo.

# 11. Human Review / Quality Model

Add a section explaining the workflow.

## Heading

> **Automation where it works. Review where it matters.**

Suggested workflow:

### 1. Ingest
Source content arrives from Word, PDF, spreadsheet, scan, image, or legacy bank.

### 2. Structure
AssessmentCore extracts and organizes stems, options, answers, interactions, metadata, and media.

### 3. Validate
Automated rules identify structural problems, missing fields, malformed items, and inconsistent content.

### 4. Review
Ambiguous or unsupported items are flagged for human review instead of silently passing.

### 5. Deliver
Validated content is returned in the required structured format or prepared for the target platform.

This should replace any “absolute precision” style messaging.

# 21. Accessibility

Maintain basic accessibility standards.

Required:
- semantic headings in logical order
- form labels
- alt text for meaningful images
- descriptive link text
- keyboard-accessible navigation
- visible focus states
- sufficient contrast
- no text embedded only inside images when that text is essential
- decorative graphics should not create noisy screen-reader output

For the handwritten/demo image, alt text should describe the transformation without pretending to reproduce every word.
